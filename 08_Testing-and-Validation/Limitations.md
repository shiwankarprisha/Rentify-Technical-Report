# Limitations

The current Rentify implementation is an interactive prototype and therefore has several limitations.

## 1. Frontend-Only Implementation

The prototype does not currently include a production backend or REST API.

## 2. Simulated Data

Property, verification and user information used in the prototype is demonstration data.

## 3. No Persistent Production Database

Browser local storage is used for prototype state instead of a production database.

## 4. Simulated Document Verification

Ownership and identity document handling is represented for demonstration purposes.

The prototype does not independently authenticate documents against government records.

## 5. No Live Registry Integration

The prototype does not currently connect to government property registries or other external verification databases.

## 6. No Machine-Learning Recommendation

The current ranking mechanism is deterministic and rule-based.

It does not use machine-learning recommendation or collaborative filtering.

## 7. No Automated AI Document Verification

AI-based document forgery or authenticity detection is not implemented.

## 8. Limited Fraud Detection

The prototype demonstrates flagged listings and scam-awareness content but does not contain a trained fraud-classification model.

## 9. No Production Authentication

The prototype uses role switching for demonstration and does not provide production-grade authentication or authorization.

## 10. No Production Security Guarantees

The prototype should not be used to handle real identity or ownership documents.

## 11. Limited Evaluation Data

The prototype has not been evaluated using a large real-world rental dataset or controlled user study.

## 12. Verification Limitation

A verified status should be interpreted as evidence of the defined verification checks rather than a guarantee that a rental transaction is completely risk-free.
